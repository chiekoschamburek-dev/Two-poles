# 🚀 立即开始使用

## 第一步：安装依赖

打开终端，进入UI目录：

```bash
cd D:\桌面\project\project\UI
npm install
```

等待安装完成（约1-2分钟）。

如果要用**实时摄像头**（可选，只用演示回放则无需此步），再拉一次端侧资产：

```bash
npm run camera:assets
```

它会下载 `pose_landmarker_lite.task`（5.5 MB）并复制约 27 MB 的 wasm 到 `public/mediapipe/`（该目录不进 git，重新 clone 后需再跑一次）。注意：摄像头只在 **https 或 localhost** 下可用，用 `vite --host` 的局域网 http 地址打不开。

## 第二步：启动开发服务器

```bash
npm run dev
```

看到以下输出表示成功：
```
  VITE v5.x.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

## 第三步：打开浏览器

访问: **http://localhost:5173**

您将看到原型界面。7 个页面都有实际界面（建档 / 概览 / 计划 / 跟练 / 餐食 / 周报 / 设置），数据只存在本机浏览器；深度不均的几处见文末"尚未实现的深度"。

## 💡 常见问题

### Q: 如何切换模式？
A: 点侧边栏顶部的"当前模式"卡片，选择大众模式 / 运动员模式。切换会立即生效、写入 localStorage，并弹出确认 Toast。窄屏（<1100px）下先点左上角汉堡按钮打开抽屉。

### Q: 演示可以暂停吗？
A: 可以，且已修正：暂停时冻结累计时间，恢复后从原处继续，不会再一次性跳到末尾；切到后台标签页再回来同样不会跳（单帧增量被钳制在 250ms）。

### Q: 能看到运动员模式吗？
A: 能，用上面的模式切换即可。注意两种模式目前只有 Hero 文案与指标数字不同；周期计划、负荷与 RPE 记录仍未实现。

### Q: 数据保存在哪里？
A: 跟练结果（`sessions`）、模式与档案会存进 localStorage 的 `twopoles_state`，刷新后保持，可在跟练页的汇总卡看到累计条数。界面上的餐食、周报、"本周完成 2/3"等仍是硬编码演示常量。

### Q: 一定要先建档吗？
A: 不强制。没建档时概览顶部会有一条"还没完成建档"的引导横幅，其余内容照常可看可点；点横幅或侧边栏"个人档案"进入三步表单即可。建档后称呼、头像与"为什么适合你"的文案会按档案来，档案 id 也会挂到训练记录上。

### Q: RPE 不填会怎样？
A: 就是"未记录"——存的是 `null` 而不是 0。以后做周报时，这类记录不参与负荷计算（时长×RPE），并在数据质量说明里单列，不会被当成"很轻松的训练"。

## 🎯 下一步建议

### 如果要继续开发：

1. **识别 → 计数联动**（最有价值）
   - 用 `usePoseCamera` 的关节角写 `ready→down→up→count++` 状态机，带迟滞与最短间隔
   - 用 `visibility` 门控：半身出镜或遮挡时暂停计数
   - 保留现有的增量时钟与组数逻辑，只替换事件来源

2. **计划调整持久化**
   - 让"接受调整"真正改写本机计划数据，`PlanAdjustment` / `PlanChange` 落地为可回滚的版本记录

3. **按档案计算推荐**
   - 用 `availableTimes` / `equipment` / `restrictions` 过滤 `planRules` 的动作池，替换现在的固定周一/三/五安排

4. **餐食增强**
   - 食物库与模糊搜索、拍照识别（需要模型或后端）、运动员模式的训练日营养时间线
