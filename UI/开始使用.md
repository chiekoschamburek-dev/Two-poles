# 🚀 立即开始使用

## 第一步：安装依赖

打开终端，进入UI目录：

```bash
cd D:\桌面\project\project\UI
npm install
```

等待安装完成（约1-2分钟）。

如果要用**实时摄像头**（可选，只用演示回放则无需此步），再拉一次端侧资产：

```bash
npm run camera:assets
```

它会下载两个端侧模型（姿态 5.5 MB、食物识别 6.9 MB）并复制约 27 MB 的 wasm 到 `public/mediapipe/`（该目录不进 git，重新 clone 后需再跑一次）。注意：摄像头只在 **https 或 localhost** 下可用，用 `vite --host` 的局域网 http 地址打不开。

## 第二步：启动开发服务器

```bash
npm run dev
```

看到以下输出表示成功：
```
  VITE v5.x.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

## 第三步：打开浏览器

访问: **http://localhost:5173**

您将看到原型界面。7 个页面都有实际界面（建档 / 概览 / 计划 / 跟练 / 餐食 / 周报 / 设置），数据只存在本机浏览器；深度不均的几处见文末"尚未实现的深度"。

## 🎯 可以立即体验的功能

### 1️⃣ 查看仪表板
- 打开浏览器自动显示仪表板
- 第一行就是"今天做什么"：`轻松跑 20 分钟`，下面一行是可用时间、场地与要避开的条件

### 2️⃣ 体验摄像头演示
1. 点击主页上的 **"开始跟练"** 深墨色按钮
2. 进入摄像头演示页面
3. 自动播放坐站训练演示：
   - ✅ 实时计数（目标次数取自动作元数据：坐站 8 次 / 弯举 10 次）
   - ✅ 置信度显示 (0.88-0.93，进入页面的瞬间是 0，会先显示"识别较差")
   - ✅ 动作阶段提示 + 组间 6 秒倒计时，共 2 组
   - ✅ 暂停/继续、跳过本组、结束并记录、手动修正都可用
   - ⚠️ 骨架图是按阶段位移的 SVG 示意，不是真实关键点渲染（取景框已改成深底，骨架用深底专用色）
4. 想验证真识别：点标题下方的 **"实时摄像头"** chip，浏览器会请求摄像头权限
   - ✅ 画面变成你的实时影像 + MediaPipe 端侧骨架，状态卡多出一行**膝/髋/肘角度**与 FPS，"置信度"改为显示关键点可见度
   - ✅ **计数由关节角状态机驱动**（`useRepCounter`：迟滞区间、最短阶段时长、3 帧平滑、遮挡冻结、停滞重置、抖动不计入），支持机位校准；界面会显示当前计数来源
   - ✅ 拒绝授权、无摄像头或不支持（http 局域网访问）时自动退回"演示回放"，并把原因显示在 chip 右侧
   - ⏳ 首次点击要加载约 38 MB wasm+模型（本地 `public/mediapipe/`，非联网），稍慢属正常

### 3️⃣ 浏览训练计划

### 5️⃣ 记录一餐（可拍照）
1. 进"饮食记录"，点任意一餐的 **记录早餐 / 记录午餐 / 记录晚餐** 或"添加加餐"

## 💡 常见问题

### Q: 如何切换模式？
A: 点**页头右侧的"运动员模式 / 大众模式"芯片**，会先列出差异与未完成计划，确认后才生效、写入 localStorage，并弹出 Toast。窄屏（<1100px）下页头同样有这个芯片，不需要先开抽屉。

### Q: 演示可以暂停吗？
A: 可以，且已修正：暂停时冻结累计时间，恢复后从原处继续，不会再一次性跳到末尾；切到后台标签页再回来同样不会跳（单帧增量被钳制在 250ms）。

### Q: 能看到运动员模式吗？
A: 能，用页头的模式芯片切换即可。运动员模式会显示周期阶段、距离/RPE 负荷、四周周期视图与训练日用餐时间线；两种模式的计划分别保存，互不覆盖。

### Q: 数据保存在哪里？
A: 全部在本机 localStorage 的 `twopoles_state` 里：档案、模式与切换历史、训练记录（含 RPE 反馈）、餐食记录、计划版本与历史、"1 单位=几克"的口径、隐私偏好与主题。刷新后保持，可在设置页导出 JSON/CSV 或一键清除。**没有后端，也不会上传任何东西。**

### Q: 一定要先建档吗？
A: 不强制。没建档时概览顶部会有一条"还没完成建档"的引导横幅，其余内容照常可看可点；点横幅或脊底的"档案"进入三步表单即可。建档后称呼、头像与"为什么适合你"的文案会按档案来，档案 id 也会挂到训练记录上。

### Q: RPE 不填会怎样？
A: 就是"未记录"——存的是 `null` 而不是 0。以后做周报时，这类记录不参与负荷计算（时长×RPE），并在数据质量说明里单列，不会被当成"很轻松的训练"。

### Q: 热量数字准吗？
A: 只当量级参考。它有三个明确假设：① 食物在内置的 56 条参考值里（**这些数字未与《中国食物成分表》逐项核对**，全部标 `verified: false`）；② 单位→克数按演示假设（碗 200 g、份 120 g…），可改成你自己的口径并记住；③ 单张照片估不出分量，所以份量由你填。因此它永远显示为 ±25% 的区间而不是一个精确数，份量没填或食物没收录就直接不显示。

### Q: 拍照识别会把照片传上去吗？
A: 不会。识别用的是浏览器内的 EfficientDet-Lite0（约 6.9 MB，`npm run camera:assets` 已下载到本机 `public/mediapipe/`），照片只在本地解码推理，组件关闭时立即释放临时 URL。覆盖范围只有 COCO 的 9 个可食类，中餐大多认不出——这是模型能力边界，不是坏了。
