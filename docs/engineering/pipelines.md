# 动作分析与食物图片识别：流程与算法

本页是两条"看图/看视频出数据"链路的现状说明：它们各自吃什么输入、用什么模型与算法、在哪里不猜、失败时怎么降级。代码位置见文末索引。

## 0. 总览

| | 动作分析 | 食物图片识别 |
|---|---|---|
| 输入 | 相册视频 1–60 秒，≤ 200 MB | 照片（拍照/选图）≤ 12 MB |
| 推理位置 | **纯本机**（视频不出设备） | **二选一**：服务端代理的视觉模型，或本机 EfficientDet-Lite0 |
| 模型 | MediaPipe Pose Landmarker（33 关键点） | 云端多模态模型 / COCO EfficientDet-Lite0（9 类） |
| 产物 | 测量值 + 关注项 + 参考观察 + 六层证据 | 食物条目 + 类别 + 可选份量 / 热量区间 |
| 明确不做 | 不评分、不判"姿势对错"、不替代专业评估 | 不判断真实分量、不评价吃多吃少、不给营养/医疗建议 |
| 失败策略 | 证据不足 → 降级为"参考观察"或不出结论 | 输出不合规 → 整条作废，不补猜 |

两条链路共享同一套工程原则：**模型输出必须过校验层；拿不准就显式降级；所有口径带版本号。**

# 一、动作分析

## 1.1 输入与预处理

1. **输入约束**：mp4 / webm / mov，1–60 秒，≤ 200 MB。
2. **抽帧（两阶段，V2）**：
   - 全片 **5 fps** 粗扫（`COARSE_FPS`），找"活跃区间"；
   - 活跃区间内 **15 fps** 精扫（`ANALYSIS_FPS`）；若粗扫判定为步态候选，精扫用 **30 fps**（`GAIT_FPS`，最长 20 秒）；
   - 粗扫点刻意落在 15 fps 网格上，精扫直接命中同一份推理缓存，**总推理次数不超过旧方案**。
   - 不再用"视频前 10 秒"代表整段（旧实现的缺陷已修）。
3. **帧缩放**：长边压到 **960 px**（`POSE_INPUT_MAX_WIDTH`）再送模型（模型输入本身只有 256×256）。
4. **姿态估计**：MediaPipe Pose Landmarker 输出 33 个关键点（`x/y/visibility`）。推理在 Worker 内优先 GPU delegate；不可用时回落实时主线程 / CPU（状态文案如实显示实际后端）。

## 1.2 质量门

- 单帧可用：**关键点可见度 ≥ 0.5**（`MIN_FRAME_VISIBILITY`）；
- 全段质量：可用帧占比 `usableRatio`，过低时预检直接标降级并说明原因；
- 姿态质量模块（`pose/quality.ts`）额外产出肩髋膝踝等关键点的可见度分布，供规则准入使用。

## 1.3 活跃区间（能量法）

- 逐帧"能量" = 关键点位移的归一化和（用躯干长归一化，抵消远近差异）；
- 时间平滑：窗口 ≈ `fps × 0.3`（取奇数帧）；
- 阈值：`threshold = quiet + 0.35 × (peak − quiet)`，下限 `minEnergy = 6`；
- 区间合并：间隔 < 500 ms 合并；短于 900 ms 的区间丢弃；
- 输出：活跃窗口列表 + 每秒能量曲线（进证据，便于解释"为什么只分析了这一段"）。

## 1.4 视角估计（多证据，V2）

旧实现只用"全片 max(肩宽,髋宽)/躯干高"，下蹲到底躯干变矮会让比例虚高。V2 改为：

1. **只取直立帧**：膝角 > 150° 且躯干高度处于前 20% 分位；
2. **主特征**：宽高比校正后的 `max(肩宽, 髋宽) / 躯干高`：
   - ≤ **0.22** → 侧面（`side`）
   - ≥ **0.58** → 正面/背面（`front`）
   - 中间：若远侧可见度差 > **0.16** → 降级为**斜侧**（`oblique`）
3. **连续量**：由投影比反推 yaw（参考投影比 0.82），只作连续量，未做 mocap 校准；
4. **分段估计**：每 2 秒一个窗口，窗口内至少 2 条直立帧才给该区间定类；
5. **可靠性**是质量分数，**不是正确概率**；类别 `unknown` 是合法结果——宁可让用户选，也不硬猜。

## 1.5 动作识别

1. **大类分流**（`recognition/family.ts`）：力量 / 步态 / 核心保持 / 上臂；
2. **步态证据**（`temporal/gait.ts`）：
   - 周期估计用左右腿差值的自相关，峰强 **r ≥ 0.3** 才可信，周期搜索范围 **0.5–1.6 s**（步频 75–240 步/分）；
   - 触地事件：归一化抬升显著度 ≥ **0.06**（躯干长），最小间隔 **250 ms**；
   - 自相关足够强时优先用周期法，触地只用于接触时间等指标；两者都不够可信时返回 `null`/`0`，由上层降级。
3. **软打分**（`recognition/actions.ts`）：深蹲/硬拉/弯举/平板/坐站/跑步/走路按特征打分（膝屈深度、髋铰链占比、躯干前倾、踝膝水平位移、左右交替、节奏），比较 top1 与 top2 的**分差**；
4. **未知拒识**：分数不够或分差过小 → 不硬判，返回候选让用户确认；**不再出现"自信地判错"**。

## 1.6 分段与计数（状态机）

- 自适应状态机（`segmentation/reps.ts`）：迟滞 **8°**、最短阶段 **250 ms**、最短重复 **500 ms**、最长阶段 **8 s**、可见度下限 **0.5**；
- 遮挡：允许短时宽限（离线宽限 1 s），超时则丢弃该次；
- 多策略合并：主关节计数 + 副关节补漏，减少半程/遮挡漏计；
- 目标切换只认"位置持续迁移"，避免机位抖动被当成新动作；
- **半程动作单列** `partial`，不混进完整重复；
- 浅蹲/半程/遮挡三类边界都有合成序列断言（`eval:synthetic`）。

## 1.7 测量

| 量 | 算法 |
|---|---|
| 关节角（膝/髋/肘） | `acos(u·w / (|u||w|))`，向量为"关节→相邻两个关键点" |
| 躯干角 | 肩中点到髋中点向量与竖直方向的夹角 |
| 步态周期 / 步频 | 自相关主峰周期 → 步频；触地数折半作交叉校验 |
| 接触时间、接触膝角、左右对称 | 触地窗口内的统计量 |
| 角速度 / 角加速度 | **Savitzky–Golay** 局部二次拟合求导（窗口 0.5 s、order 2），缺失/遮挡帧断线，不补 0 |
| 髋部归一化速度 | 髋中点竖直位移 ÷ 躯干长，再求一/二阶导 |

## 1.8 规则与准入

1. **阈值来自文献**，按视角分套（侧面看深度/躯干，正面看对称/膝内扣）；
2. **准入闸**：`ruleRequirementFailure` 检查关键点、视角可靠性、重复次数是否足够——不够就**不出结论**，只出测量值；
3. **重复性闸**：`applyRecurrenceGate` 要求同类问题在多组/多次里复现；
4. **关注项置信度**：`可见度均值 × 视角可靠性 × 越界幅度 × 重复次数基线(0.5/0.7/0.85/1)`；置信度只用于**标注与排序**，不改阈值；
5. 模板 `findingsReady: false`（弯举、平板、坐站等）**只出测量值**，不产出关注项（ADR-0003）。

## 1.9 证据与版本

- 六层证据 JSON：`pose → action → view → event → metric → finding`，记录"测到了什么、为什么这么判、哪些没评"；
- 单条证据 **compact 到 ≤ 6 KB** 后才落盘/同步；
- 版本常量：引擎 v2 / 特征 v1 / 配置 v2 / 规则 **v4** / 模型 `rule-baseline-0`（尚无学习模型）；
- 长期趋势按 `ruleVersion` + `engineVersion` **断线**，口径变了不混算。

## 1.10 真值与评测边界

- 7 条真实素材人工标注在 `apps/web/scripts/motion-eval/truth/`，状态 `provisional`（agent 标注、未人工复核）；
- 冻结夹具 `fixtures/` + `manifest.json`（sha256），`npm run eval:replay -- --gate` 先验签再评测；当前 **7/7 通过**；
- 步态周期允许 **±1–2** 容差（2D 标注不确定度），**重复次数仍要求精确**；
- 所以"全绿"只代表"引擎与标注一致"，**不等于**人体工效学准确率，对外不要这样表述。

# 二、食物图片识别

## 2.1 入口与同意

- 入口：记录饮食 → 拍照 / 选图；结果页默认直接保存，低置信度项标出，想改再展开；
- **云端通道必须勾选"发送照片给模型"的同意**，未勾选时不能拍照/选图；本机通道不发图；
- 原图默认不保存；开启"保存餐食照片"时只存 **256 px 缩略图**到本机 IndexedDB。

## 2.2 图片预处理

- 大小上限 **12 MB**，超限直接报错，不静默压缩；
- 长边压到 **1024 px**，导出 JPEG **质量 0.85**（`prepareModelImage`）；
- 缩略图：长边 256 px、JPEG 0.7、白底填充（`makeFoodThumbnail`）。

## 2.3 通道选择

1. 设置页配了自定义模型，或服务端默认模型可用 → **云端识别**；
2. 否则 → **本机识别**；
3. 云端失败（未配置/网络/上游/超时）→ 页面提示可改用本机识别或手动补录，**不会自动回退**（避免用户在不知情时把照片发给另一条通道）。

## 2.4 云端识别（视觉模型）

- 走同源 `/api/llm/chat`：本地由 Vite 中间件、线上由阿里云 ESA 边缘函数 `apps/api/llm.js` 代理；**模型密钥只在服务端/函数变量**，浏览器只拿到 `{ available, model }`；
- 请求：`temperature = 0.1`，120 秒超时（可取消），图片以 `image_url` data URL 发送；
- **system prompt 的硬约束**：
  1. 只输出一个 JSON 对象，不要 Markdown、不要解释；
  2. 只列照片里可见的食物，没有就返回空数组；
  3. 每项必须有 `foodName / category / confidence(0–1) / uncertain`，`category` 只能取枚举值；
  4. 份量与单位只在能合理判断时给，单位只能取内置枚举；
  5. 热量区间可选，看不清就省略；
  6. **餐次由客户端按拍摄时间判断，模型不许猜**；
  7. 不给医疗、治疗、减重或竞技营养建议，不评价吃得多不多。

## 2.5 本机识别（端侧）

- MediaPipe `ObjectDetector` + **EfficientDet-Lite0**（CPU delegate），首次加载约 20 MB wasm+模型，超时 60 秒；
- 参数：`scoreThreshold = 0.35`、`maxResults = 16`；
- 只映射 COCO 中 **9 个可食类**：苹果、香蕉、橙子、西兰花、胡萝卜、披萨、热狗、甜甜圈、蛋糕；
- 同一类多个检测框合并取最高分；无可食类命中 → 明确报"只覆盖 9 类"，**不猜**；
- 本机通道不给份量与热量（照片推不出重量是常识，不是缺陷）。

## 2.6 输出校验层（两条通道共用）

模型输出先过 `validateRecognitionObject`，任何一条不合格就丢弃该条并记录 warning；全部不合格 → 整条结果作废，不生成记录：

| 字段 | 规则 |
|---|---|
| 条目数 | 最多 **12** 条（超出截断并提示） |
| `foodName` | trim、压缩空白、≤ 40 字；空名丢弃 |
| `confidence` | **必填**；0–1（>1 且 ≤100 视为百分数归一）；非法即丢弃（不补造数字） |
| `category` | 必须是 10 类枚举之一；非法先按内置目录推断，再不行标"其他"并提示 |
| 份量 | `size > 0 且 ≤ 5000`，单位必须在 `UNIT_GRAMS` 枚举里，否则留空 |
| 热量 | `0 ≤ low ≤ high ≤ 5000`，否则忽略 |
| `uncertain` | 模型显式 true，或置信度 < **0.6**，或类别为"其他"，或混合菜 → 标不确定 |
| 去重 | 同名（忽略大小写）保留置信度更高的一条 |

## 2.7 餐次与餐食结构

- **餐次**：按本地时间窗推断（早餐 05:00–10:29 / 午餐 10:30–14:59 / 晚餐 15:00–21:00，其余为加餐）；模型不参与；
- **结构分析**（`analyzeMeal`）：
  - 关注 8 类覆盖：谷薯、蔬菜、水果、蛋、奶、肉、豆、坚果；
  - `missingCategories` 按**当天累计**计算（早餐不会被要求覆盖水果和奶类）；
  - 类别"其他"或混合菜、且用户未逐项确认 → 进"待确认"；
  - 免责文案与实际产出保持一致（有没有热量区间，写不同的句子）。

## 2.8 热量粗估（可选）

- 只有设置开启时才显示；
- 依赖填写的份量 × 内置演示参考值，误差带 **±25%**（`ESTIMATE_BAND`）；
- 参考值标注"未与权威成分表逐项核对"；混合菜不拆原料就不估算。

## 2.9 错误与降级

错误码：`image`（读图失败）/ `network` / `not_configured` / `upstream`（模型或超时）/ `invalid_output`（JSON 或字段不合规）/ `empty`（没有食物）。
所有错误都**不生成记录**，页面给出下一步：重试、换本机识别、手动补录。

# 三、共同原则

1. **不猜**：缺字段、看不清、证据不足 → 显式说"没有/不确定"，不补造数字。
2. **不评分**：动作分析不给"对错/分数"，食物识别不给"健康评分"。
3. **可解释**：每个结论都能追到测量值、阈值与来源；证据 JSON 可回看。
4. **版本化**：规则/引擎/特征/配置/目录都有版本号，口径变化时趋势断线、历史不重算。
5. **本机优先**：动作视频不出设备；食物照片只在用户勾选同意后发模型。
6. **失败显式**：降级路径有文案，不静默回退。
